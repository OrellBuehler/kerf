# Editor UI Implementation Plan

**Goal:** Implement the six approved UI review improvements and correct timeline timecode.

**Architecture:** Keep existing editor operations and saved custom dock layouts. Change the default workspace, introduce reusable collapsible Inspector sections, reorganize Agent and Export controls, and share an engine-aligned timeline timebase between counters and keyboard stepping.

**Tech Stack:** Svelte 5, TypeScript, Dockview, Bun, Playwright browser verification.

## Tasks

1. Update `frontend/src/lib/layout.ts` to place the timeline below Media, Preview, and a shared Inspector/Agent group. Keep layout restoration and reset behavior; adapt `layout.test.ts` to check layout validity without relying on old group indices.
2. Add tested `frontend/src/lib/timecode.ts` helpers for the first timeline video source's timebase and frame counting. Use them in `state.svelte.ts`, Toolbar, Preview, and keyboard frame stepping. Cover mixed rates, missing video, fractional rates, and frame boundaries.
3. Compact `AgentPanel.svelte` connection status and collapse setup and suggestions. Put reviews before work in progress, wrap task prompts, and explicitly label queue actions and waiting tasks.
4. Introduce `InspectorSection.svelte` with native keyboard-accessible disclosure controls and summaries. Keep trim and volume visible; collapse advanced controls without changing their behavior.
5. Enlarge shared buttons, timeline controls, and frequently read metadata. Verify track header and lane height stay aligned.
6. Reorganize `ExportDialog.svelte` around preset, destination, resolution, and readable quality. Keep codec/rate control/audio encoding/container options in Advanced and retain validation and export behavior.
7. Run focused tests, full frontend tests, Svelte checks, production build, and browser checks at 1280×800 and 1440×900. Exercise disclosures, queueing, export options, panel switching/reset, and timeline selection. Inspect screenshots and review the final diff.

UI layout and styling are verified in the browser; tests cover timebase logic and existing layout validation.
